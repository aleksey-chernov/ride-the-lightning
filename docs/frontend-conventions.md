# Frontend conventions (`ui/`)

React 19 + TypeScript, Vite, Tailwind v4, shadcn/ui, react-query, Zustand, MapLibre. This page is the rulebook: where code goes, how it's named and imported, and which tool enforces what. When a rule and the code disagree, fix one of them.

## Structure

```
ui/src/
├── main.tsx                 entry: <Providers><App/></Providers>
├── app/                     app shell: composes features, owns page layout
│   ├── app.tsx
│   ├── providers.tsx        QueryClientProvider (and future app-wide providers)
│   └── layout/              header, footer
├── api/                     GENERATED by Orval from the backend's OpenAPI; committed, never edited by hand
│   ├── endpoints/{tag}/     fetch functions + react-query hooks per OpenAPI tag
│   └── models/              response/param types
├── features/{feature}/      one folder per feature (live-map, stats, …)
│   ├── containers/          smart: call hooks/stores, wire data to components
│   ├── components/          presentational: props in, callbacks out
│   ├── hooks/               feature hooks (effects, subscriptions)
│   ├── stores/              Zustand stores (client state)
│   ├── lib/                 stateful helpers and integrations (stream client, MapLibre glue), with their CSS
│   ├── utils/               pure functions
│   ├── constants/           static config (layer styles, URLs)
│   └── types/               feature-only types
├── shared/                  cross-cutting, used by ≥ 2 features or the app
│   ├── components/          presentational building blocks (e.g. connection-badge)
│   ├── components/ui/       shadcn components (generated into the repo, then ours)
│   ├── lib/                 fetch-json (HTTP client for src/api), shadcn utils
│   ├── stores/              Zustand stores read by ≥ 2 features or the app (none yet)
│   ├── utils/               pure helpers shared across features (e.g. units: formatSeconds)
│   └── types/
└── styles/globals.css       Tailwind + theme tokens only
```

Folders inside a feature are created on demand: `stats` has no `hooks/` yet, and that's fine.

## Layers and the dependency rule

```
api  ←  shared  ←  features/*  ←  app
```

- `shared/` must not import `features/` or `app/`.
- A feature must not import `app/` or **another feature**. If two features need the same thing, move it to `shared/`; if one feature must react to another (e.g. "fly the map to this hotspot"), wire it in `app/` (props, callbacks, or a store the app passes down).
- `app/` may import anything; it's where features meet.
- `src/api/` is generated; only its HTTP client (`shared/lib/fetch-json.ts`) is hand-written.

Enforced by Oxlint (`no-restricted-imports` overrides per folder in `.oxlintrc.json`).

## Containers vs components

- **Containers** (`containers/`) call hooks and stores, decide what to show, and pass data down. Few of them; usually one per feature entry point (`LiveMap`, `StatsPanel`).
- **Components** (`components/`) are presentational: everything comes in through props, events go out through callbacks. No stores, no react-query, no fetching. Local UI state (open/closed, hover) and imperative widget glue (a MapLibre ref) are fine.
- When unsure, write a component; promote it only when it really needs to orchestrate state.

## State

| Kind | Where | Example |
|---|---|---|
| Server state (data owned by the backend) | react-query, via the generated hooks in `src/api` | `useGetVersion()` |
| Client state shared across components | a Zustand store per concern, in `features/*/stores/*.store.ts` | `useLiveFeedStore` |
| Client state used by ≥ 2 features | a Zustand store in `shared/stores/*.store.ts` | none yet |
| Remembered UI preferences | Zustand `persist` middleware (localStorage), in the store that owns them | none yet |
| High-frequency data | plain objects outside React, read by timers | `StrikeBuffer` (strikes for the map) |
| Local UI state | `useState` in the component | a hover flag |

- Logic lives in stores, hooks and `lib/`/`utils/`, not in JSX.
- Select narrowly from stores (`useLiveFeedStore((s) => s.status)`) so components re-render only for what they use.

## API client (Orval)

- `src/api/` is generated from `GET /api/v1/docs/docs.yaml` by `pnpm api:generate` (backend must be running), then formatted with Prettier. Commit the result.
- Config: `ui/orval.config.ts`. React-query hooks + fetch, kebab-case files, no index/barrel files, plain response bodies.
- The SSE endpoint is tagged `stream` in the backend and excluded: browsers consume it with `EventSource`.
- **Response contract** (backend, `rtl.http.ResponseContract`): collections are always present (`[]`, never omitted) and marked required in OpenAPI, so generated types have `strikes: StrikeResponse[]`, not `strikes?: …`. Import `rtl.http.ResponseContract.given` in every file that declares response types.
- After a backend API change: run the backend, `pnpm api:generate`, check `pnpm build`, commit `src/api` with the backend change.

## Naming

| Thing | Pattern | Example |
|---|---|---|
| Any file | kebab-case | `strike-map.tsx`, `use-live-strikes.ts` |
| Component | `PascalCase` export in `kebab-case.tsx` | `StrikeMap` in `strike-map.tsx` |
| Hook | `useX` in `use-x.ts` | `useLiveStrikes` |
| Store | `useXStore` in `x.store.ts` | `useLiveFeedStore` in `live-feed.store.ts` |
| Pure helpers | `x.utils.ts` | `geo.utils.ts` |
| Test | next to the file, `x.test.ts` | `strike-buffer.test.ts` |
| Props type | `Props` (local to the file) | `type Props = { count: number }` |
| Constants | `UPPER_SNAKE_CASE` | `MAP_STYLE_URL` |
| API types (backend) | `XResponse` / `XRequest` | `StrikeResponse` |

Exports are named, never default (the generated API is the only exception).

## Imports

- Path aliases for everything outside the current folder: `@api/*`, `@shared/*`, `@features/*`, `@app/*`. Same-folder imports use `./`. Never `../` (lint error).
- **No barrel files** (`index.ts` that re-exports): import the file that defines the thing. Barrels hide dependencies and create cycles (lint error).
- Order is applied by Prettier, in blocks separated by a blank line:
  1. Node built-ins and third-party (`react`, `zustand`, `maplibre-gl`, …)
  2. Project, by layer: `@api` → `@shared` → `@features` → `@app`
  3. Same-folder `./` (side-effect CSS imports last)
- Type-only imports use `import type { X }` or `type X` inline. TypeScript's `verbatimModuleSyntax` requires it, and Oxlint enforces it.

## TypeScript

- `strict`, plus `noImplicitReturns`, `noImplicitOverride`, `noPropertyAccessFromIndexSignature`, `noUnusedLocals/Parameters`, `erasableSyntaxOnly` (no `enum`, no constructor parameter properties).
- `type`, not `interface` (lint error), for props, data shapes and contracts alike.
- Classes are rare (stateful helpers like `StrikeBuffer`); private fields use `#field` (real runtime privacy), not `private`.

## Styling

- Tailwind utilities in markup; `cn()` (from the `cn` package) to merge conditional classes. Class order is sorted by Prettier.
- Theme colours are CSS variables in `styles/globals.css` (shadcn tokens); change the theme there, not per component.
- `src/shared/components/ui/` is shadcn code copied into the repo: edit it freely, but re-running `shadcn add --overwrite` replaces local edits.
- Plain CSS only when Tailwind can't express it (keyframes, pseudo-elements), **colocated** with the code that uses it (`features/live-map/lib/strike-flash.css`, imported by `strike-flash.ts`). Custom properties for its tunables at the top of the rule.
- Stylelint (`stylelint-config-standard`) checks CSS conventions; Prettier formats it.

## Testing

- Vitest; tests sit next to the code as `*.test.ts(x)`.
- Test pure logic first (`utils/`, `lib/`), then components if a behaviour is worth pinning.
- Names read as sentences: `describe('StrikeBuffer')` + `it('evicts strikes older than the window')`.
- No real timers or network: pass `nowMs`/clocks in, or use `vi.useFakeTimers()`.

## Formatting and editor

- Prettier (`ui/package.json` → `"prettier"`): single quotes, semicolons, width 160, LF; plugins sort imports and Tailwind classes.
- `.editorconfig` (repo root): 2-space indent, LF, final newline; `ui/` files get width 160 and single quotes, so IntelliJ matches Prettier.
- IntelliJ: Settings → Languages & Frameworks → JavaScript → Prettier → *Automatic*, *Run on save*; Stylelint → *Automatic*; Oxlint plugin (or run `pnpm lint`).

## What enforces what

| Rule | Tool | Where |
|---|---|---|
| Layer boundaries, no `../`, no `@/` | Oxlint `no-restricted-imports` | `.oxlintrc.json` |
| kebab-case files | Oxlint `unicorn/filename-case` | `.oxlintrc.json` |
| No barrels, no import cycles, no default exports | Oxlint `oxc/no-barrel-file`, `import/no-cycle`, `import/no-default-export` | `.oxlintrc.json` |
| `type` over `interface`, `import type` | Oxlint `typescript/*` + TS `verbatimModuleSyntax` | `.oxlintrc.json`, `tsconfig.app.json` |
| Hooks rules and effect dependencies | Oxlint `react/rules-of-hooks`, `react/exhaustive-deps` | `.oxlintrc.json` |
| Formatting, import order, Tailwind class order | Prettier + plugins | `package.json` |
| CSS conventions | Stylelint | `.stylelintrc.json` |
| Types | `tsc -b` (part of `pnpm build`) | `tsconfig.app.json` |
| Exact dependency versions | pnpm `saveExact` | `pnpm-workspace.yaml` |

## Commands (`cd ui`)

| Command | Does |
|---|---|
| `pnpm dev` | Vite dev server on :5173, proxies `/api` to :8080 |
| `pnpm lint` / `pnpm lint:fix` | Oxlint + Stylelint (with autofix) |
| `pnpm format` / `pnpm format:check` | Prettier write / check |
| `pnpm test` | Vitest |
| `pnpm build` | Type-check + production bundle |
| `pnpm api:generate` | Regenerate `src/api` (backend running) |
| `pnpm dlx shadcn@latest add <name>` | Add a shadcn component into `shared/components/ui` |

## Adding a feature

1. **Backend** first if it needs data: endpoint + `XResponse` types (with `ResponseContract.given`), tests.
2. `pnpm api:generate` with the backend running; commit `src/api`.
3. `src/features/{feature}/`: a container that calls the generated hook (and a store if there's client state), presentational components it renders, pure logic in `utils/` with tests.
4. Compose it in `app/app.tsx`. Cross-feature interaction goes through the app, never feature → feature.
5. `pnpm lint && pnpm format:check && pnpm test && pnpm build`.
